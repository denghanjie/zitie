# 全库逐字校勘台账

本台账覆盖诗词库 1,555 条记录和教材库 216 篇正文。**全量比对已执行，不代表全量校勘已经完成，也不作零错字承诺。** 完成状态及实时统计以 `public/library/collation.json` 为准。

## 方法与状态

- 校验正文哈希并逐字比较汉字序列；另比较去除排版空白后的全部 Unicode 字符，保留标点、缺字、增字及换字差异。差异偏移从 0 起计。
- 篇名、作者和全文共同用于识别同一作品；自动相似匹配只产生候选，不能据此改署名、拼接正文或自动补全缺字。
- `compared`：正文汉字与指定对照本一致，标点差异另列。它并不证明两份可能同源的资料均无误。
- `retained`：已记录版本用字的保留决定；不宣称逐字等同所有教材印次。
- `excerpt`：正文与对照本片段一致，但尚未确认序文、组诗、节选边界，暂不开放填入。
- `pending`：有待裁定差异、署名冲突或缺少合适对照本，暂不开放填入。
- `blocked`：存在缺字占位符、姓名截断、残留现代夹注等已知问题，暂停使用，禁止由 AI 猜补。

公开整理本只提供对照证据；它们可能来自共同的古诗文网资料，**不能冒充独立权威底本**。义务教育各印次课本的正文仍需以对应印次教材页复核；不能用诗词库的通行版本强改教材通假字与异文。

## 修订与证据

- `editorial.json`：逐条保留改前／改后完整正文、标题作者、哈希、修订理由和对照出处。部分修订属于选用通行版本，不一律称旧本为错别字。
- `collation-evidence.json`：每条记录使用的候选对照文本及出处；无法匹配时明确留空。只保存公版原文与题名作者事实，不收录现代译文、鉴赏或教材图片。
- `quality.json`：由脚本生成的前端状态表。
- `public/library/collation.json`：完整逐字及标点差异，可从网站“正文校勘记录”下载。
- 既有 6 篇／8 处现代用字修正在 `src/text-corrections.js` 中保留，后续修订在 `src/editorial.js` 中统一应用。

## 参考资料固定版本

1. [aopao/chinese-gushiwen](https://github.com/aopao/chinese-gushiwen/tree/c2345d0abf2404b8b3601e4afc2e8fd12f90d6c8/guwen)，10 个文件、10,000 条古代作品记录，只提取原文、题名、作者事实。
2. [weiyinfu/GuWen](https://github.com/weiyinfu/GuWen/blob/5b1b936a57dd2be2ff4887719ad6f39c8a456066/guwen.json)，原仓库说明来源为古诗文网，篇目不是严格的《古文观止》222篇，不能以书名推定对应关系。

3. [zhouzhaoxin/GuShiWen](https://github.com/zhouzhaoxin/GuShiWen/tree/d328fb960b51430bb7271ed8e091cc1a48f1d463)，提取唐诗古代原文、题名和作者，不提取译注赏析。
4. [JasonWade001/chtxt](https://github.com/JasonWade001/chtxt/tree/6623a458ec1ef0578e0ebe75c543555fbd37c1d3/n.%E8%92%99%E5%AD%B8)，使用《宋词三百首》《千家诗》，去除现代括注和书末标记。它自身也出现署名冲突及合并记录，仅作对照资料，不能因仓库自称“精校”就视为权威。

## 更新规则

1. 比对候选必须指向固定版本和记录索引；人工裁定时记录具体异文与版本依据。不可仅为提高通过率改状态。
2. 增补正文修改后同时更新证据中的正文哈希，检查对应参考文本是否仍适用；不能只改哈希绕过校勘。
3. 执行 `node scripts/build-library.mjs <原资料目录>`、`node scripts/build-textbooks.mjs`、`python3 scripts/build-collation.py`，再执行 `pnpm test`、`pnpm build`。
4. 测试会拒绝台账漏项、正文哈希变化后未更新证据、生成产物过期；并检查缺字记录不可填入、旧草稿不会覆盖用户手改。
5. 未编辑且可精确识别的旧版导入草稿使用已记录修订；不能匹配的旧导入内容要求重新选择。手动粘贴的文字保持用户输入，由用户决定内容；含缺字占位符时阻止生成。
