# 本地检索与来源核对：浏览器验收

本检查面向本机 Codex 或人工测试。只验证本地运行的候选版本，不发布、不修改生产服务器、不创建密钥、不购买外部服务。不要把真实凭据写入命令、截图、测试报告或提交记录。

## 已完成与尚未完成

交付环境中已通过检索、取消/超时、提供商状态、真实本地语料来源校验、版本化草稿和历史记录的程序测试，并完成服务端 JSX 渲染检查。

**浏览器点击流程和截图尚未在交付环境中验证。** Chromium 在加载页面前因操作系统权限拒绝内部 `socket()` 而退出；一次受审查的额外权限重试也未解决。以下浏览器步骤必须在能正常运行 Chromium 的本机完成。没有因此验证百度、DeepSeek 或维基文库的真实连通性。

## 1. 无外部提供商的真实本地流程

使用项目已有依赖，不需要额外安装 Python 后端依赖。开两个终端：

```sh
# 终端一：只启用本地语料。env -u 不会显示密钥，也不修改已保存设置。
env -u DEEPSEEK_API_KEY -u BAIDU_API_KEY \
  WIKISOURCE_ENABLED=0 ZITIE_STATE_DIR=/tmp/zitie-local-smoke \
  python3 server/ai.py

# 终端二：默认 127.0.0.1:5173；此地址在本地接口允许的 Origin 中。
npm run dev
```

打开 `http://127.0.0.1:5173/`，在浏览器开发者工具中记录网络请求。首次后端启动会先建立本地索引，等它开始接受请求后再测试。

- 打开“查找诗文”。百度提示应为“尚未配置”，百度和 AI 按钮不可用；“查找”仍可用。
- 分别搜索“黄巢 不第后赋菊”“黃巢 不第後賦菊”和“满城尽带黄金甲”。普通查找应请求 `/api/poetry/search`，不请求 `/hints` 或 `/discover`，不访问 DeepSeek/百度。
- 本地扩展语料应包含《不第後賦菊》、作者“黃巢”。两个整理本分开显示，不能合成一个“已校勘”结果：
  - `全唐诗/poet.tang.41000.json` 第 173 条：“衝天香陣透長安”
  - `御定全唐詩/json/733.json` 第 21 条：“沖天香陣透長安”
- 两者都应指向 GitHub 固定版本 `b8594f81a89752241442f2ce267d6f66f96704ee`。核对框内仍保留对应“衝／沖”等原字形；检索繁简归一不应改写正文。
- 再搜索“菊花 元稹”，应显示相应候选；不要要求全部结果仅有同一个短题，长题/正文也可能匹配。
- 选一个已知待校勘/暂停使用的内置篇目（可从“正文校勘记录”选择），勾选“显示待校勘篇目”查看。它仍不能直接填入，也不能借扩展语料绕过旧有状态。
- 停止后端后再做普通查找：静态资料库仍应提供其匹配结果；扩展语料必须明确提示不可用，不能将此误报为整个资料库为空。

## 2. 明确核对、编辑、重新打开

先恢复后端，搜索并选择一个真实扩展候选。

1. 未勾选核对确认时，“用已核对的正文替换练习内容”不可用。
2. 自行打开该固定来源，核对作者、篇名及所选正文。需要摘选时手动编辑，不应自动截断 3000 字以上正文。
3. 勾选确认后再改作者、篇名或正文：确认状态必须清除。
4. 重新核对确认并填入。主界面应标为“用户核对，未经资料库校勘”，不能显示“文字已对照”。
5. 刷新页面：所选正文和原字形不变。原始来源证据与所选正文应分别保存。
6. 编辑练习内容、保存字帖，再从“我的字帖”打开。最新编辑应恢复，原始来源记录仍在；生成时不应把正常用户摘选误判为来源损坏。
7. 在独立测试浏览器配置中，备份测试草稿后，将其中来源记录的 `version` 改为旧值，或只修改 `content` 而不修改其他字段。重新打开后应阻止生成并要求重新查找核对；不能因旧的 `editedAfterReview: true` 绕过检查。不要用真实或唯一的个人历史记录做破坏性测试。

## 3. 无凭据的延迟、取消与部分失败模拟

可选脚本 `scripts/smoke-local-first-ui.py` 使用模拟的 `/api/poetry/*` 响应，不访问任何上游 API。它使用虚构诗文测试 UI，**不代表已经人工核对真实文献**。脚本不会安装依赖；仅在本机已有 Python Playwright 和 Chromium 时运行。

```sh
# 终端一；与上面的 5173 会话分开，或先停止它。
npm run dev -- --port 4175

# 终端二；需要现有 Python Playwright 与 Chromium。
# 若 Chromium 不在 PATH，可通过 CHROMIUM_PATH 指定已安装的浏览器。
python3 scripts/smoke-local-first-ui.py
```

可用 `ZITIE_SMOKE_URL` 指定本地 Vite 地址，`ZITIE_SMOKE_OUTPUT` 指定截图目录；默认截图目录是 `/tmp/zitie-local-first-smoke/`。地址必须是自己启动的本地测试实例，不能指向生产站点。

脚本预计检查：

- AI 响应故意延迟时，本地候选先出现且可选择。
- 选中后修改正文并确认，随后到达的网络结果不能清空编辑或确认状态。
- DeepSeek 失败、百度成功、维基文库未启用分别展示；不能仅用总状态“已完成”掩盖失败。
- 百度摘要只有外链，没有选择正文或“已核对”填入入口。
- 明确确认后填入，刷新和历史恢复保留来源证据；正常编辑仍可通过完整性检查。
- “停止等待”保留已显示的本地结果，迟到的旧网络响应不能重新出现。
- 改查找词后旧结果清空；下一次普通查找不应发送 AI 请求。

没有这些现有依赖时，直接按上述条目手动检查，不要为运行测试临时执行未知来源的安装命令。若脚本失败，记录第一处断言/浏览器错误和当时的页面；不要把未运行的步骤写成通过。

## 简体默认显示回归

- 检索“黄巢 不第后赋菊”，检查候选篇名、作者、预览和填入正文为简体（如“黄巢”“冲天香阵透长安”）。不同原始版本仍是独立候选。
- 展开“对照原始来源（原字形）”，核对“後”“黃”“沖/衝”等原字形及原文 SHA-256；转换不代表校勘。
- 勾选核对后填入，生成逐字练习与整篇临摹，确认预览和导出与编辑框相同；复制编辑框文本也应为简体。
- 保存、刷新、从历史恢复，确认简体文本及原始来源证据均保留。手动加入繁体字再保存，应保留编辑而非自动重转。
- OpenCC 加载失败或尚未完成时，应显示明确提示，扩展候选不能填入；取消不应永远显示“正在准备”，重新查找可以重试。
- 教材选篇与内置检索也默认使用简体，原有质量限制和转换前对照正文保留；繁体查找关键词仍能匹配。
